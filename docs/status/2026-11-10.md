## TL;DR

- **Phase 0 is done**, re-scoped to a single machine. One Docker image (Python 3.11 +
  Blender 4.2) renders on the EC2 GPU instance and on a local NVIDIA machine with the
  same commands.
- **There is no S3.** On EC2, data lives on the EBS volume at `/app/synthrig`, and the
  instance-store NVMe is render scratch at `/scratch`.
- **Disk space** is reported by `cloud.py disk` and `cloud.py status`, and by
  `infra/check.sh`. Renders refuse to start, and workers stop, below 20 GiB free.
- **A GPU bug was fixed.** Every frame had been rendering on CPU even with
  `device: GPU`. The demo frame now takes 8.7 s on the A10G (OptiX), against 55 s on CPU.
- **All 44 tests pass** in the image, including the Blender geometry tests.
- **Next:** commit Phase 0, then start `TASK_scenes.md` Phase 1.

## Repository layout cleanup (after the Phase 0 commit)

- The root holds only `README.md`, `LICENSE`, `AGENTS.md`, `pyproject.toml`, `uv.lock` and
  the git files.
- `run.py` became `python -m synthrig` (`synthrig/__main__.py`).
- `CLAUDE.md` moved to `.claude/CLAUDE.md`, and `.dockerignore` to
  `infra/docker/Dockerfile.dockerignore`.
- `.python-version` was removed: `pyproject.toml` already pins Python 3.11.
- `infra/test_access.py` was removed; use `python -m infra.access.check`.
- `infra/ec2/push_log.sh` was removed: check logs go to the data root, not git.
- `infra/ec2/check_ec2.sh` moved to `infra/check.sh`, the pre-merge check (no CI), with
  logs in `<data_root>/logs/check/`.
- New `.secrets/` folder for git push credentials. It is ignored by git and by the Docker
  build; only its README is tracked.
